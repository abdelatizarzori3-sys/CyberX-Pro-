# CyberX Pro — MVP محلي

نسخة أولية قابلة للتشغيل محليًا لإدارة الحساب والمؤسسة والأصول والتفويضات وطلبات التقييم المحلية وسجل التدقيق. الواجهة عربية ومتجاوبة.

> **حدود السلامة:** إنشاء طلب تقييم يسجل بيانات وصفية محليًا فقط (`RECORDED`). لا تتصل هذه النسخة بالأصول ولا تنفذ استطلاعًا أو فحصًا شبكيًا أو استغلالًا. وجود تفويض مسجل لا يعني أن النظام تحقق قانونيًا من مستنده. لا تستخدم النسخة ببيانات عملاء حقيقية ولا تعتبرها جاهزة للإنتاج.

## التشغيل عبر Docker

```bash
docker compose up --build
```

افتح `http://localhost:8000`. تحفظ بيانات SQLite في volume باسم `cyberx_data`. تعمل الحاوية بمستخدم غير جذري، ولها فحص جاهزية يختبر اتصال التطبيق بقاعدة البيانات.

## التشغيل محليًا

يتطلب Python 3.11 أو أحدث:

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
uvicorn backend.app.main:app --reload
```

افتح `http://127.0.0.1:8000`. توثيق API التفاعلي في `/docs` مناسب للتطوير المحلي فقط.

## تجربة المسار الأساسي

1. أنشئ حسابًا بكلمة مرور لا تقل عن 12 حرفًا؛ ينشئ التسجيل مؤسسة أولية.
2. أضف أصلًا وصفيًا.
3. سجّل نطاق التفويض ومدته وأقر بأن لديك مستند تفويض.
4. سجّل طلب تقييم؛ لا تقبل الخدمة الطلب دون تفويض سارٍ، ولا يتصل الطلب بالأصل.
5. راجع حالة التفويض، وألغِه عند الحاجة؛ الإلغاء يمنع تسجيل طلبات جديدة ويُكتب في سجل التدقيق.

## تشغيل الاختبارات

```bash
pip install -r requirements-dev.txt
pytest -q
```

تغطي الاختبارات الحاجة إلى جلسة، جاهزية قاعدة البيانات ورؤوس الحماية، التفويض الساري والمنتهي والملغى، بقاء رفض الطلب في سجل التدقيق، عزل بيانات مؤسستين، وإبطال الجلسة بعد تسجيل الخروج. يشغّل GitHub Actions مجموعة الاختبارات وفحص تجميع Python عند الدفع أو فتح Pull Request.

## نقاط API الأساسية

- `POST /api/v1/auth/register`, `POST /api/v1/auth/login`, `POST /api/v1/auth/logout`
- `GET /api/v1/me`
- `GET|POST /api/v1/assets`
- `GET|POST /api/v1/authorizations`, `POST /api/v1/authorizations/{id}/revoke`
- `GET|POST /api/v1/scans` — تسجيل طلب محلي غير تنفيذي فقط
- `GET /api/v1/audit-logs`
- `GET /api/v1/health` — فحص liveness؛ و`GET /api/v1/ready` — فحص جاهزية قاعدة البيانات

## ما هو موجود وما يزال خارج النطاق

الموجود: FastAPI، SQLite للتجربة المحلية، كلمات مرور مخزنة باستخدام scrypt، جلسات Bearer قصيرة العمر قابلة للإبطال، أصول وتفويضات، طلبات محلية غير نشطة، سجل تدقيق، واجهة عربية، رؤوس حماية أساسية للمتصفح، فحص جاهزية، حاوية غير جذرية، واختبارات أولية وCI.

غير الموجود: PostgreSQL وmigrations، MFA وRBAC وعضويات المؤسسات، إدارة ثغرات أو حوادث، ملفات أدلة، عمال تنفيذ، أي فحص أمني فعلي، AI، إشعارات، فوترة، Flutter، ومراقبة ونسخ واستعادة إنتاجية. قبل تطوير هذه الأجزاء، راجع `docs/ROADMAP.md` و`docs/SECURITY.md`.

## إعدادات

- `CYBERX_DB_PATH`: مسار ملف قاعدة البيانات (الافتراضي `cyberx.db`).
- `CYBERX_SESSION_HOURS`: عمر الجلسة بالساعات (الافتراضي 12، والحد الأدنى ساعة واحدة).

لا تضع أسرارًا أو بيانات حقيقية حساسة في المستودع أو بيئة العرض التجريبي.

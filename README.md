# CyberX Pro — MVP تشغيل محلي

نسخة أولية قابلة للتشغيل تركّز على أساس المنصة: تسجيل الدخول، إنشاء مساحة مؤسسة، تسجيل الأصول، توثيق التفويض، وفتح مهام تقييم آمنة مع سجل تدقيق. الواجهة عربية وتعمل من المتصفح.

> **حدود الأمان:** هذه النسخة لا ترسل أي اتصال إلى الأصول ولا تنفذ فحوصاً شبكية أو استغلالاً. «مهمة التقييم» تسجل طلباً محلياً فقط وتتحقق من وجود تفويض ساري للأصل. لا تستخدمها كمنتج إنتاجي أو كبديل عن مراجعة أمنية.

## التشغيل باستخدام Docker

```bash
docker compose up --build
```

ثم افتح http://localhost:8000 . البيانات محفوظة في volume باسم `cyberx_data`.

## التشغيل محلياً

يتطلب Python 3.11 أو أحدث:

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
uvicorn backend.app.main:app --reload
```

افتح http://127.0.0.1:8000 . توثيق API التفاعلي متاح على `/docs`.

## تجربة سريعة

1. أنشئ حساباً من صفحة الدخول؛ ينشئ التسجيل مؤسسة خاصة بالحساب.
2. أضف أصلاً باسم وصفي (مثلاً `موقعي التجريبي`) وحدد نوعه.
3. سجّل إقرار التفويض ومدة سريانه لهذا الأصل.
4. أنشئ مهمة تقييم؛ لا تقبل الخدمة المهمة إلا إذا كان التفويض سارياً.
5. راجع سجل المهام والأحداث في لوحة التحكم.

## ما هو مشمول وما هو غير مشمول

المشمول: API بـFastAPI، تخزين SQLite للتجربة المحلية، كلمات مرور مخزنة باستخدام scrypt، جلسات Bearer محدودة المدة، فصل بيانات الحسابات حسب المؤسسة، أصول، تفويضات، مهام محلية غير نشطة، ولوحة ويب عربية بسيطة.

غير المشمول بعد: PostgreSQL/RLS، MFA، دعوات وأدوار متعددة، Workers حقيقية، فحوص أمنية، ملفات أدلة، ذكاء اصطناعي، التنبيهات، الفوترة، وتطبيقات Flutter/Next.js. يجب تنفيذ هذه المكونات ومراجعتها واختبارها قبل وصف المنتج بأنه مكتمل أو نشره للإنتاج.

## إعدادات اختيارية

- `CYBERX_DB_PATH`: مسار قاعدة البيانات (الافتراضي `cyberx.db`).
- `CYBERX_SESSION_HOURS`: عمر الجلسة بالساعات (الافتراضي 12).

لا تضع أسراراً أو بيانات حقيقية حساسة في بيئة العرض التجريبي.
